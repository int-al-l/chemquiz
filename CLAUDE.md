# ChemQuiz — working rules

Two people work on this repo, each with their own Claude. These rules keep
their changes from colliding. Follow them in every session, for every change.

## Before starting any change

```bash
git fetch origin
git switch main && git pull --rebase origin main
git switch -c <author>/<short-topic>     # e.g. nik/quiz-timer, alex/new-deck
```

Never commit directly to `main`. One branch per change; keep it small and
focused, so it can be merged the same day.

## While working

- Commit often, with clear messages (what changed and why).
- If the branch lives longer than a few hours, bring in the other person's
  work before continuing: `git fetch origin && git rebase origin/main`.
- Run the checks before pushing:
  ```bash
  npm run lint && npm test
  cd backend && python -m pytest -q
  ```

## Finishing

```bash
git fetch origin && git rebase origin/main   # resolve conflicts here, not on GitHub
git push -u origin <author>/<short-topic>
```

Then open a pull request into `main`. CI (lint, frontend tests, backend tests)
runs on it automatically; merge only when it is green. Prefer "Squash and
merge". Delete the branch after merging.

If a rebase hits a conflict in a file the other person owns or just changed,
keep both intentions — don't silently drop their lines. When unsure, stop and
ask the user.

## Generated files — do not edit or commit by hand

These are rebuilt automatically by `.github/workflows/pages.yml` after every
merge to `main`, so committing them from a branch only causes conflicts:

- `docs/` (the GitHub Pages build)
- `src/demo/data.json` (made from `backend/seed_data.py`)

If you ran `npm run build:pages` or `tools/make_demo_data.py` locally, discard
those changes before committing: `git checkout origin/main -- docs src/demo/data.json`.

`backend/seed_data.py` is generated by `catalog/synthware/build.py`. Edit
`catalog/synthware/curate.py` and re-run the build rather than hand-editing it,
and tell the other person in the PR description, since this file conflicts badly.

## Who is working on what

Before starting something big, check open pull requests and branches
(`git branch -r`) so two people aren't building the same thing. Put a short
description of the plan in the PR as early as possible (a draft PR is fine).

## Project notes

Decisions and status are kept in `claude/chemquiz-v2-notes.md` in the
"Chem Quiz" Claude project. Update it when a change alters a decision recorded
there. See README.md for how to run the site.
